# 安程

**子女把行程排好，长辈打开就能看懂。**

把爸妈发来的行程短信（或微信里那段乱七八糟的文字）粘进来，自动排成一份**长辈能看懂的大字页面**，生成链接 / 二维码 / 6 位码发过去 —— 短信和邮件也能直接发。长辈打开就能看，不用注册、不用登录、不用装 App。

---

## 它解决什么问题

- 子女收到的行程原文是「10月8号早上G7102次从上海虹桥站到北京南站 09:30发车 13:45到」这类黑话，转发给爸妈等于没转
- 爸妈在手机上看不清小字、找不到关键信息，还要在电话里反复确认「几点？哪个站？」
- 现成方案要么要求装 App、要么要求注册、要么把行程数据上传到云端

所以这个应用**核心功能没有后端**：行程数据只存在使用者的浏览器里，分享链接本身携带数据（可选的通知服务只负责"把链接发出去"这一件事，见下文）。

## 功能一览

### 子女端

| 页面 | 能力 |
|---|---|
| 身份选择 | 爸妈（免登录直达）/ 子女（账号体系） |
| 账号 | 注册（账号名/邮箱/手机号）、登录（任一标识）、最近账号、删除账号；数据按账号隔离 |
| 导入行程 | 粘贴原文 → 三智能体管线解析 → 预览核对 → 入库；草稿自动保存 |
| 行程列表 | 搜索（行程名 / 车次 / 站点）、草稿提示、删除（两步确认） |
| 行程详情 | 问题汇总（error 优先）、逐段手动修正、**手动新增/删除段**；改完自动重算人话与语音；**卡片 Todo 清单**（三档优先级）、**「出站后往哪走」到达指引**、**查目的地天气**；顶部安全提醒（长辈求助 / 平安到达超时） |
| 家人 | 长辈该怎么称呼这个人（可自由输入，不是从子女视角选「爸爸」）、**「他对我的称呼」**、**家人分组**（一人可属多组，分享时按组一键带上）、手机号、微信号/QQ、备注 |
| 分享 | 有效期（7/30/90 天）+ 长辈端显示（字大小 / 主题）+ **本次包含哪些家人** + **首选联系人**（长辈按住求助打给谁）→ 链接 + 6 位码 + 二维码 + **发给长辈（短信/邮件）**；**分享给其他子女**（自包含邀请链接 / 6 位码） |
| 接收行程 | 贴链接或输 6 位码 → 预览 → 把别人分享的行程**复制成自己的新行程**（重复导入会被拦住） |
| 我的 | 数据备份导出 / **从备份文件恢复**（按 id 去重合并）、**清理缓存与残留**、清空数据、退出、切换账号 |

### 长辈端：一个按钮一个页面

`#/e/<token>` 免登录直达，底栏三个按钮对应三个独立页面（长辈不用在一页里找东西）：

| 路由 | 页面 |
|---|---|
| `#/e/<token>` | 今日行程：页顶**紧急求助**（长按 1 秒）+ 绝对时刻倒计时（「离 09:35 出发还有 2 小时 15 分」）+ 编号行程卡 + 清单打勾 + 「听一遍」语音播报 |
| `#/e/<token>/calls` | 家人电话：称呼（大字）→ 号码/微信 → 备注 → [拨打] [微信] 两个大按钮；首选联系人带「出事先打他」 |
| `#/e/<token>/show` | 显示设置：字大小（标准/大/超大）× 主题（**日间 / 高对比 / 夜间**）+ 屏幕常亮开关 + 勾完自动读开关 + 「回到主页面」 |
| `#/e` | 输码页 / **「继续上次的行程」**（记住这台手机）/ 链接过期 / 链接损坏（都没有底栏） |

**长辈端 11 项优化（本轮交付）**：① PWA 离线 + 断网横幅与安装引导 ② 记住这台手机 ③ 屏幕常亮（Wake Lock，不支持则静默隐藏）④ 勾完自动引导下一段 + 绝对时刻倒计时 ⑤ 走完 5 秒撤销 ⑥ 紧急求助长按按钮（拨首选 + 位置短信）⑦ 平安到达确认（本机提醒 + 子女端「妈妈可能还没到」）⑧ **闽南话播报**（离线音频包，可切换）⑨ 行程长图保存 ⑩ 到达指引置顶 ⑪ 目的地天气。

- **这一端不出现产品名，也没有 logo**：长辈只需要看到「今天怎么走」
- 子页面都有整宽的「返回今日行程」，显示页还有显式的「回到主页面」，都不依赖浏览器返回键
- 「微信」不假装能唤起 App：把号复制好，让长辈到微信/QQ 里搜
- 适老化硬指标：**三种主题的正文对比度都 ≥7:1（AAA）、正文 ≥28px 且字重 ≥600、主按钮 ≥72px、触控区 ≥60×60、零动画**（换主题、放大字号后仍逐条断言）

### 分享四形态

1. **链接**：自包含（数据在链接里），任何设备打开都行
2. **二维码**：248px 承载，M 级优先；**保证每格 ≥2.4px**（扫得动）
3. **6 位码**：只在这台设备输入有效（同机快速通道）
4. **短信 / 邮件**：见下一节

### 短信 / 邮件：双通道

浏览器自己发不出短信和邮件，所以有两条**都真能送到**的路径：

| 通道 | 什么时候用 | 怎么工作 |
|---|---|---|
| 本机 App（零配置） | 没配服务商时 | 调起用户手机上的短信/邮件 App，正文里写好链接与 6 位码，用户按发送 |
| 服务端发送 | 配了服务商密钥时 | 前端 POST 到 `/api/notify`，服务端调真实服务商直接送达 |

- 判定是自动的：探测 `/api/notify/config`；没配、请求失败或超时 3 秒 → 回落本机，并把**实际走了哪条路**如实写在页面上
- 密钥只在服务端读环境变量，**前端零密钥**；服务默认只接受同源请求
- 支持的服务商：阿里云短信（HMAC-SHA1 签名）、Twilio、Resend 邮件、通用 webhook 网关（自建/企业微信/钉钉中转都能接）

## 技术栈

运行时依赖：**Vue 3 + GSAP**（GSAP 只用于子女端的三处编排：页面切换、列表入场、6 位码逐位翻入），其余全部自研 —— 这也是「离线可用」的前提：

| 模块 | 说明 |
|---|---|
| `src/core/agents.js` | 三智能体串行管线：解析原文 → 翻成人话 → 合理性检查；分享载荷的紧凑打包与还原；行程「游玩安排」段、卡片 Todo、到达指引 |
| `src/core/qr.js` | 自研二维码引擎（Model 2 / 字节模式 / ECL L·M / 版本 1–25）+ 可扫性评估 `qrInfo` |
| `src/core/share-codec.js` | 分享链接编解码（v2 紧凑载荷 + base64url + FNV-1a 校验；兼容 v1 老链接；v3 子女邀请包） |
| `src/core/store.js` | 账号隔离的 localStorage 持久化 + 备份合并 + 家人分组 + 长辈端显示偏好白名单 + 「记住这台手机」 |
| `src/core/sync.js` | 双轨同步：服务端 `/api/sync/*` + 同设备 BroadcastChannel / localStorage 镜像，失败静默 |
| `src/core/elderState.js` | 长辈端按房间隔离的「走完 / 收起 / 提醒已读 / 清单打勾」状态（白名单校验） |
| `src/core/upcoming.js` | 出发提醒分级、绝对时刻倒计时、平安到达检查点（纯函数，可单测） |
| `src/core/map.js` | 在线地图瓦片数学（OpenStreetMap 栅格瓦片，零依赖，不引地图库） |
| `src/core/sos.js` | 紧急求助：首选联系人、位置链接、`sms:` / `tel:` 深链、号码脱敏 |
| `src/core/weather.js` | 目的地天气：穿衣提示文案（纯函数）+ 服务端 `/api/weather` 调用，失败静默 |
| `src/core/elderVoice.js` | 闽南话播报：设备台语声音 → 离线音频包 → 如实提示，三级降级 |
| `src/core/export.js` | 日历 `.ics` 导出（手写 RFC5545）+ 行程长图（canvas 2D 手绘，子女端与长辈端共用） |
| `src/core/notify.js` | 短信/邮件双通道：深链构造、通道探测、回落判定 |
| `src/core/motion.js` | 子女端动效层（GSAP + reduced-motion 统一关断） |
| `src/core/spring.js` | 弹簧物理（可打断 / 速度交接 / reduced-motion 降级）——抽屉拖拽用 |
| `src/core/router.js` | 自研 hash 路由 |
| `src/core/accounts.js` | 账号体系（密码哈希：安全上下文走 Web Crypto，否则降级弱哈希） |
| 其余 | `ai.js`（AI 补全/识字契约）、`model.js`（模型配置）、`checklist.js`（行前清单） |

构建：Vite 6。测试：Node 内置 `node:test` + Playwright（不进运行时依赖）。
可选服务端：`server/`（零依赖，只用 `node:http`）。

## 快速开始

> 更细的步骤、三种跑法的区别、常见问题（端口占用 / 找不到浏览器 / 模型下载），见 **[构建与运行说明.md](./构建与运行说明.md)**。

```bash
npm install

npm run dev          # 开发服务器 http://localhost:5190
npm run build        # 构建到 dist/
npm run preview      # 预览生产构建（5190，纯静态，没有 /api）
npm run build:single # 产出 dist/安程-单文件.html（双击即开，file:// 可跑）

# 想看完整效果（含长辈端↔子女端实时同步、目的地天气）：
node server/notify-server.mjs --serve-dist   # http://localhost:5180（同源发布 dist + 全部接口）
```

### 想真的发短信/邮件

```bash
cp server/.env.example .env     # 填阿里云 / Twilio / Resend / webhook 任一条
node server/notify-server.mjs --serve-dist   # 同源发布 dist + 通知接口（默认 5180）
```

不填也能用：前端会自动改用用户手机上的短信/邮件 App。
本地联调可用假服务商：`node server/mock-provider.mjs`，把 `*_BASE_URL` 指到 `http://localhost:5181/<provider>`。

| 脚本 | 作用 |
|---|---|
| `npm run dev` / `build` / `preview` | 常规开发与构建 |

## 测试体系

测试代码行数多于产品代码，是刻意为之：

- **单元**（`tests/unit/`）：解析管线口语用例矩阵、二维码用第三方 `jsQR` 做往返校验（不自证）、**分享载荷的长度上限与"解码后 = 编码前"**、账号与备份纯函数、长辈端显示偏好白名单、短信/邮件深链与通道回落、阿里云签名向量、弹簧物理、压力
- **端到端**（`tests/e2e/`）：真实浏览器走查（注册→导入→分享→长辈端）、两功能点组合、大数据量压力（40 段/20 条）、适老化硬指标逐条断言 + 视觉基线、**长辈端三页导航与"不放产品名"**、**家人称呼视角与微信复制**、**通知双通道（服务端真发送打到假服务商 + 未配置回落本机）**
- **视觉基线**（`tests/screenshots/`）：桌面 6 页 + 移动端 4 页 + 长辈端三页；只生成基线不做像素 diff（跨平台字体渲染下像素比对是噪音），结构性事实一律用测量断言（如 390px 无横向溢出、二维码每格 ≥2.4px）
- **约定**：新增测试文件必须登记进 `tests/run-all.mjs` / `tests/run-e2e.mjs` 的显式列表（不用目录扫描，避免空套件误报）；所有依赖「今天」的断言动态生成日期，绝不写死

## 部署

纯静态产物，任何静态托管都能跑（`base: './'` 用相对路径，支持子路径托管）：

```bash
npm run build   # 把 dist/ 丢到任意静态托管即可
```

- **Netlify / Vercel / GitHub Pages**：构建命令 `npm run build`，发布目录 `dist`
- **自托管**：仓库内提供 `Dockerfile` + `nginx.conf`（nginx 托管 dist）
  - 应用用 **hash 路由**，服务端**不需要** SPA rewrite 兜底规则
  - `sw.js` 必须设为不缓存，否则新版本发不出去（nginx.conf 已处理）
  - 要开真实短信/邮件，再单独跑 `node server/notify-server.mjs`（建议与站点同源，前面挂反向代理；服务自身也能用 `--serve-dist` 直接一起发布）
- **PWA**：生产构建 + http(s) 下自动注册 service worker，可「添加到主屏幕」并离线打开；离线预缓存是安装时解析 index.html 得到的（构建产物文件名带哈希）
- **单文件**：`dist/安程-单文件.html` 可直接发给别人，双击用浏览器打开（`file://` 下不含 PWA）

> 说明：`Dockerfile` 与 CI 配置是**可交付参考**，未在开发沙箱内实际执行 `docker build`。

## 设计说明

- **中性纸白 + 编辑式排版**：底色 `#F6F7F5` 中性纸面 + 单一强调色信号绿 `#0B6B45`（白字对比 6.55:1，AA 达标）；靠字阶、对齐、细线分隔说话，卡片不用阴影（阴影只留给抽屉/吐司这类浮层）
- **数字一律等宽**（车次、时刻、6 位码）：长辈和子女都要逐位核对
- **长辈端与子女端是两套视觉契约**：子女端有页面入场/列表/6 位码三处 GSAP 编排（reduced-motion 下全部关断）；长辈端零动画、**日间 / 高对比 / 夜间**三主题 + 白卡 + 信号绿主操作，正文对比度由机器断言守着
- **品牌标记**：一条从出发到抵达的路线（起点实心圆 → 一段平路 → 终点圆环），纯几何单色，16px 下可辨；favicon / PWA 图标 / 顶栏字标三处同源
- 所有间距/字号/动效/焦点环都有 token（`src/styles/global.css`），页面只消费不另造

## 诚实边界

这些不是"待办"，是设计取向，写清楚比藏着好：

- **核心功能没有后端、没有云同步**：行程与账号只存在这台设备的浏览器里，换台设备就是另一个世界
- **短信/邮件需要你自备服务商密钥**：仓库提供适配器与本地假服务商，但没有你的云账号，无法替你开通；不配就用用户手机上的 App 发
- **登录失败统一提示「账号或密码不对」**：不泄露某个账号是否注册过
- **不识别截图/照片里的字**（原方案本身不含 OCR）：遇到这类描述会标「待人工确认」
- **农历日期只识别不换算**：保留原文写法并标记，绝不编一个公历日期
- **非法日期（如平年 2/29）保留字面并标记**，不静默改成 3 月 1 日
- **6 位码只在设置过的那台设备有效**，跨设备请用链接/二维码
- **浏览器打不开微信/QQ**：长辈端的「微信」按钮是把微信号（或手机号）复制到剪贴板并给出提示，需要长辈自己到微信里搜号；不做「假装能唤起 App」的链接
- **紧急求助不能替你「自动发短信」**：长按 1 秒后是「调起拨号 + 把位置短信交给系统短信 App」，用户按发送才算发出（浏览器没有这个权限，不假装能做到）
- **闽南话播报的音频是机器合成的**：来自 Meta MMS-TTS 的 `nan` 模型，**未经母语者试听**，台罗/白话字模板也未经母语者逐句校对；模型许可 **CC-BY-NC-4.0（非商用）**，商用请换音源（细节与替换办法见 `public/audio/nan/NOTICE.md`）
- **在线地图与天气依赖外部网络**：地图瓦片来自 OpenStreetMap、天气来自 Open-Meteo（免 key，**只传城市名、不上报长辈位置**）；连不上就如实不显示，不影响看行程
