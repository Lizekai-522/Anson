# 安程 · 第五轮改造方案（长辈端可用性 + 跨端同步 + 位置）

> 目标：把长辈端从「能看」做到「能勾、能折、会提醒」，并把长辈端的动作与位置**回传**给子女端。
> 已确认的决策（来自用户）：同步走**双轨**（有服务端走服务端，没有走同设备）；定位走**长辈主动开启、开启后持续上报**；乱码问题**编码与排版都要查**。

---

## 一、现状分析（Phase 1 探索结论）

### 1.1 架构事实
- **纯前端 + localStorage**，无账号后端。账号隔离键位见 [store.js](file:///workspace/src/core/store.js#L13-L22)：`ptb:data:<accountId>`。
- **分享链接是自包含的**：[share-codec.js](file:///workspace/src/core/share-codec.js) 把 payload 压成紧凑形态 + FNV-1a 校验，`encodeShare` → `#/e/<token>`；长辈端 [ElderPage.vue](file:///workspace/src/elder/ElderPage.vue#L94-L108) 直接解码，**不经过任何服务器**。
- **可选服务端已存在**：[server/app.mjs](file:///workspace/server/app.mjs) 零依赖（只用 `node:http/fs`），同源校验 `sameOrigin()` + 可选 Bearer token；入口 [notify-server.mjs](file:///workspace/server/notify-server.mjs)，支持 `--serve-dist` 同源发布前端。
- **前端探测服务端的既有范式**：[notify.js](file:///workspace/src/core/notify.js#L42-L52) 的 `probeChannel()`（fetch + 超时 + 失败回落），本轮同步客户端照抄这个范式。

### 1.2 关键约束（不能破）
- **长辈端适老化红线**（由 [a11y.test.mjs](file:///workspace/tests/e2e/a11y.test.mjs) 机器断言）：正文 ≥28px、主按钮 ≥72px 高、触控区 ≥60×60、三主题正文对比度 ≥7:1、**全页零 CSS 动画**（该用例统计 `animationName !== 'none'` 的元素数，必须为 0）。
- 断言依赖的选择器必须保留：`.card-title` / `.card-line2` / `.card-line3` / `.bar-btn` / `.big-btn` / `.tel-btn` / `.elder-h1` / `.card`。
- 分享 payload 的紧凑格式改动会影响**二维码容量**（[agents.js packCards](file:///workspace/src/core/agents.js#L603-L632) 的注释记录了这次取舍），因此本轮**不往 payload 里塞新字段**，room 从 token 派生。

### 1.3 现状缺陷（本轮要修）
| 位置 | 问题 |
|---|---|
| [DayView.vue `.route-part`](file:///workspace/src/elder/DayView.vue#L156) | `white-space: nowrap`，长站名直接横向溢出卡片 |
| [DayView.vue `.card-line3`](file:///workspace/src/elder/DayView.vue#L159-L169) | 时间胶囊 `inline-block` + `letter-spacing`，极端缩放/长时刻会溢出 |
| [DayView.vue `.card-title-row`](file:///workspace/src/elder/DayView.vue#L129) | flex 子项无 `min-width:0`，长文本把 flex 撑破 |
| 卡片 DOM | 整卡是 `<button>`，**不能再嵌按钮**（完成/折叠按钮无处安放） |
| 导入文本 | 粘贴来的原始文本可能带零宽字符/替换字符 U+FFFD/全角空格，未净化就进卡片 |
| 长辈端 | 无「完成打勾」「折叠」「到点提醒」「回传动作」「位置共享」 |

## 三、详细改动

### A. 长辈端排版加固 + 文本净化

#### A1. 文本净化（修「乱码」的编码/脏字符一侧）
**文件**：`src/core/agents.js`

新增并导出：
```js
// 净化：去掉控制字符/零宽字符/替换字符，全角空格归一，连续空白折叠。
// 目的：粘贴来的短信原文常带 U+200B、U+FFFD、\u3000，进卡片就是肉眼可见的「乱码」。
export function sanitizeText(v) {
  if (v == null) return ''
  return String(v)
    .replace(/[\u0000-\u0008\u000B\u000C\u000E-\u001F\u007F]/g, '')
    .replace(/[\u200B-\u200D\u2060\uFEFF]/g, '')
    .replace(/\uFFFD/g, '')
    .replace(/\u3000/g, ' ')
    .replace(/[ \t]{2,}/g, ' ')
    .trim()
}
```
接入点（**只净化展示与打包，不改用户原始输入**）：
1. `buildElderCards()` 输出时对 `code / title / from / to / note` 走 `sanitizeText`。
2. `packCards()` 打包前对 `code / from / to / note / seatClass` 走 `sanitizeText`（保证链接里不带脏字符）。
3. `expandCards()` 解包后同样再过一次（**防御历史链接**）。

#### A2. 排版加固（修「超出卡片」的排版一侧）
**文件**：`src/styles/global.css`（长辈端 token 段附近）+ `src/elder/DayView.vue`

`DayView.vue` scoped 样式改动：

### B. 长辈端「完成」→ 压成一行 + C. 卡片折叠

#### B1. 卡片 DOM 重构（**关键**：去掉按钮嵌按钮）

#### B2. 完成态视觉：缩成一行（保持卡片外观）

### D. 出发时间快到 → 弹窗 → 点一下就跳到那张卡

#### D1. 纯函数：`src/core/upcoming.js`（新增，可单测）
```js
export function parseDepartAt(card)          // 'YYYY-MM-DD' + 'HH:MM' → Date（本地时区，失败返回 null）
export function upcomingList(cards, now, { leadMin = 60, secondMin = 20 } = {})
//   → [{ segId, card, departAt, minutesLeft, stage: 'lead' | 'second' }]，按 minutesLeft 升序
export function countdownText(minutesLeft)   // '还有 1 小时 5 分钟' / '还有 12 分钟' / '该出发了'
export function shouldRemind(state, item, now) // 同 stage 已 dismissed 则不再弹；已过站也弹一次（超过 5 分钟不弹）
```
规则（写死，不留选择）：
- 只对 `kind !== 'stay'` 且 **日期 = 今天** 且有 `depart` 的卡生效。
- `lead`：出发前 60 分钟内首次弹出；`second`：出发前 20 分钟内再弹一次。
- 点「知道了」写入 `dismissed[segId + ':' + stage]`；同一个 stage 不再重复弹。
- 已过出发时间 5 分钟以上不再弹（避免长辈打开页面被一堆过期弹窗淹没）。

#### D2. 弹窗组件：`src/elder/NoticePopup.vue`（新增）
- `position: fixed` 覆盖层，**零动画**（不加 transition/animation）。
- 内容：`大字`「还有 25 分钟」+ `编号 车次 出发→到达` + 两个大按钮：
  - 「去看看」→ `emit('jump', segId)`
  - 「知道了」→ `emit('dismiss', segId, stage)`
- 按钮 ≥72px 高（`.big-btn` 复用），正文对比度 ≥7:1（复用 `--el-tint` / `--el-ink`）。
- 若有多条同时到期：只弹**最近的一条**，弹窗底部显示「还有 N 条要提醒」。

#### D3. 挂载与跳转高亮
`src/elder/ElderPage.vue`：
- `setInterval(checkUpcoming, 30000)`（JS 定时器，不是 CSS 动画，不违反零动画断言）+ `onBeforeUnmount` 清理。
- 跳转：`goPage('day')` → 把 `highlightSegId` 传给 DayView。
- `DayView` 收到后 `el.scrollIntoView({ block: 'center', behavior: 'auto' })`（**必须 `auto`，不能 smooth**）+ 加 `.card-focus` 静态类（加粗 `--el-accent` 描边），6 秒后由定时器移除（无动画）。

### E. 长辈端动作 → 子女端（双轨同步）

#### E1. room 标识（不增 payload）
`share-codec.js` 导出 `fnv1a`（已有内部实现，只加 `export`）。
`src/core/sync.js` 新增：
```js
export function roomId(token)  // fnv1a(token).toString(36) + '-' + fnv1a('r'+token).toString(36)  → 12~16 字符
```
- 长辈端 token 来自 URL；子女端 token 来自 `listShares().filter(s => s.tripId === trip.id)` 里**最新未过期**的一条。
- **前置条件**：该行程必须先「生成分享链接」。没生成时，子女端「长辈动态」显示「先给长辈生成一次分享链接」，不显示空面板。

#### E2. 客户端通道：`src/core/sync.js`（新增）
```js
export async function probeSync()                 // GET /api/sync/ping，1.5s 超时，结果缓存 30s
export function subscribe(room, onChange)         // → unsubscribe
export async function push(room, events, presence?) // 失败不抛，静默回落
export function syncMode()                        // 'server' | 'device'
```
- 事件形状：`{ id, type, segId, at, data }`；`type ∈ card-done | card-undone | card-open | card-collapse | seen | loc-on | loc-off | location | trip-open`。
- 服务端可用：每 4s `GET /api/sync/<room>/pull?since=<cursor>`；`document.hidden` 时暂停轮询，回到可见立即拉一次。
- 服务端不可用（双轨的「同设备」一侧）：`BroadcastChannel('ptb-sync-'+room)` + `localStorage['ptb:sync:'+room]` 镜像（最近 100 条 + presence），**同一浏览器跨标签可同步**。
- 两条路都失败：不报错，UI 如实说明（见 G3）。

#### E3. 服务端接口：改 `server/app.mjs`（零依赖，保持风格）
```
GET  /api/sync/ping              → { ok:true, rooms:<n> }
POST /api/sync/:room/push        body { events:[…], presence? }  → { ok:true, cursor }
GET  /api/sync/:room/pull?since= → { ok:true, cursor, events:[…], presence|null }
```
- `room` 白名单：`/^[a-z0-9-]{8,32}$/`，不符返回 400。
- 内存结构：`Map<room, { seq, events:[], presence, lastAt }>`；每 room 事件环形上限 **200**；闲置 **24h** 清理；room 总数上限 **1000**（超出按 `lastAt` 淘汰最旧）。
- body 上限 32KB；沿用 `sameOrigin()`；可选 `SYNC_TOKEN` 要求 `Authorization: Bearer`。
- **只保留最新 presence，不存历史轨迹**（隐私约束，写进注释）。
- `server/notify-server.mjs` 启动日志补一行：`[sync] 同步接口：已启用`。
- `server/.env.example` 补 `SYNC_TOKEN=`。

#### E4. 长辈端埋点
`ElderPage.vue` 在 `applyPayload` 成功后 `push(room, [{type:'trip-open'}], presence?)`；`DayView` 的完成/折叠/展开各推一条；Array 内 `dismissed` 不推（本地行为）。

#### E5. 子女端「长辈动态」区块
`src/pages/TripPage.vue` 新增「长辈动态」卡片：
- 顶部状态：`已接入同步服务` / `仅同设备可见（未部署同步服务）`。
- 时间线：最近 20 条，人到化的中文描述（复用 `issueLabel` 的中文映射风格）：`长辈打开了行程` `长辈说第 2 段已经走完` `长辈收起了第 3 段的详情` `长辈开始共享位置`。
- 「长辈动态」为空时显示 `长辈还没打开过这次分享`。

### F. 子女端看长辈位置（长辈主动开启）

#### F1. 分享页开关（G2）
`src/pages/SharePage.vue` 在「长辈端显示」区块加一行：
- 「允许长辈共享位置」开关，默认 **关**；说明文案：`打开后，长辈端会出现「让子女看到我在哪」按钮，长辈点一下才会传位置。`
- 写入 `payload.prefs.shareLocation`。

`share-codec.js` 的 `f` 数组从 `[scale, theme]` 扩成 `[scale, theme, shareLocation ? 1 : 0]`；`unpackPayload` 用 `!!p.f[2]` 还原；**旧链接 `f` 只有两位 → 视为 false**（向后兼容）。
`store.js` 的 `resolveElderPrefs` 同步支持第三个字段（`shareLocation` 走布尔白名单）。

#### F2. 长辈端：`src/elder/LocationShare.vue`（新增）
- 仅在 `prefs.shareLocation === true` 且 `navigator.geolocation` 存在时渲染。
- 未开启：「让子女看到我在哪」大按钮（≥72px）。
- 点击后：
  - `location.protocol` 非 `https:`（且 host 不是 localhost）→ 显示 `这个链接不是 https，手机不让传位置`，不请求权限。
  - 否则 `getCurrentPosition` → 成功后 `watchPosition`，**节流 60s** 推送 `presence = { lat, lng, acc, at }`（经 `push(room, [{type:'location',…}], presence)`）。
  - 开启后常驻一条**明显的状态条**：「正在让子女看到你的位置」+ 「停止共享」大按钮（≥72px）。
- 权限被拒 / 超时 → 显示 `没拿到位置：需要允许定位`。
- **零动画**；仅一个 `setInterval` 节流器。

#### F3. 子女端位置卡片
`TripPage.vue`「长辈动态」区块顶部位置卡：
- 有 presence：`纬度 x.xxxxxx / 经度 y.yyyyyy`（等宽数字）+ `精度约 ±35 米` + `更新于 3 分钟前` + 「在地图上看」链接（OpenStreetMap，无需密钥：`https://www.openstreetmap.org/?mlat=..&mlon=..#map=16/..`）。
- 超过 10 分钟未更新 → 标注 `位置已 12 分钟没更新`。
- 长辈未开启：`长辈还没开始共享位置`。
- 未接入服务端：`实时位置需要部署同步服务（见 server/README 说明）`。

## 五、假设与决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 同步传输 | 双轨：server → 同设备 BroadcastChannel/localStorage | 用户确认；纯前端架构下这是唯一能同时兼顾「不部署也能演示」与「真跨设备」的方案 |
| room 标识 | 从 token 派生（不写进 payload） | 二维码容量是硬约束（packCards 的注释记录过这次返工） |
| 位置策略 | 长辈主动开启 + 节流 60s 上报 | 用户确认；隐私上最清楚 |
| 位置存储 | 服务端只留最新 presence，不留轨迹 | 降低隐私风险，且够用 |
| 位置地图 | OpenStreetMap 链接 | 无需密钥，不吃第三方配额 |
| 提醒阈值 | 60 分钟 / 20 分钟两档 | 出行场景够用，且不会淹没长辈 |
| 提醒形式 | 页内弹窗（不做系统通知） | 不引入权限申请与 SW 推送复杂度；系统通知列为后续 |
| 卡片 DOM | `button` → `section` + 内部按钮 | 按钮不能嵌套按钮（HTML 无效 + 点击事件会串） |
| 长辈端动画 | 全静态 | 适老化红线，且 a11y 用例会直接失败 |
| 完成态视觉 | 压成一行但保留卡片的底/描边/顶线 | 用户明确要求「还是原本的卡片」 |

## 六、风险与缓解
| 风险 | 缓解 |
|---|---|
| 服务端是内存态，重启后动态/位置丢失 | 明确写入 UI 文案（`仅同设备可见` / `位置已 X 分钟没更新`），不假装持久 |
| 长辈端链接是 http 时定位不可用 | 提前用 `location.protocol` 判断并给出人话提示，不弹无意义的权限框 |
| 卡片 DOM 重构可能打破现有 e2e/a11y 断言 | 保留全部断言依赖的类名；重构后先跑 `npm test` 再改别的 |
| 零动画断言被新组件破坏 | 所有新样式禁止 `animation` / `transition`；靠 `elder-a11y-plus.test.mjs` 守着 |
| 分享未生成时子女端无 room | UI 明确提示「先生成分享链接」，不显示空白面板 |
