## 0. 硬约束（不破红线）

1. **长辈端适老化红线**：正文 ≥28px、主按钮 ≥72px 高（现有 `.big-btn` 为 88px）、触控区 ≥60×60、三主题正文对比度 ≥7:1、**全页零 CSS 动画**（不写 `animation` / `transition`；进度条、撤销条用 JS 计时 + `v-if` 实现，不用 CSS 动画）。
2. **零后端依赖可降级**：所有新功能在「没有服务端」时都必须能工作或静默降级，绝不阻断核心看行程流程。
3. **不过拟合**：新词表只放结构性词汇；示例中的专有名词（地名/景点/酒店）一律不进代码与测试。
4. **隐私**：位置只在长辈主动点按后上报，只保留最新一份；紧急求助短信正文里的地图链接只用经纬度，不带轨迹。

## 2. 闽南话（#8）技术调研结论与选型

用户要求「先看 GitHub 上有没有现成的」。调研结果：

| 方案 | 许可 | 能否在本机（CPU）离线批量合成 | 结论 |
|---|---|---|---|
| **Meta MMS-TTS `nan`**（`facebook/mms-tts-nan`，VITS 架构，transformers 直接调用） | CC-BY-NC-4.0（**非商用**） | ✅ VITS 小模型，CPU 可跑，秒级/句 | **选它**（生成脚本 + 静态音频包） |
| OpenBMB **VoxCPM2** | Apache-2.0（可商用） | ❌ 2B 参数、需 ~8GB 显存（CUDA ≥12） | 记录为「有 GPU 时的商用替换方案」 |
| 清华 SATLab **DiaMoE-TTS**（IPA 多方言 MoE） | 开源（模型在 HF） | ❌ 训练/推理偏 GPU | 同上，记录备选 |
| espeak-ng | GPL | 无可靠 `nan` 音色证据 | 不采用 |

**决策**：以 `facebook/mms-tts-nan` 为生成器，产出一套**静态、离线可播**的闽南语音频包：

- 新脚本 `scripts/make-minnan-audio.py`（python3 + `torch`/`transformers`/`scipy`，wav→`ffmpeg`→mp3）+ 模板清单 `scripts/minnan-templates.json`。
- 输出 `public/audio/nan/<id>.mp3`（**单声道 24kbps**）+ `public/audio/nan/manifest.json`（id → 文件名/时长/字节数）+ `public/audio/nan/NOTICE.md`（写明模型来源、CC-BY-NC-4.0 非商用限制、替换办法）。
- 规模：**每类卡片 5 句模板 × 5 类（列车/航班/住宿/接送/游玩）+ 4 句通用 = 29 句**，脚本内置断言 **音频总体积 < 300KB**。
- 闽南语文本用**汉字**写法（如「今仔日」「欲去」「佗位」「落车」），由模板按卡片字段拼装；若 tokenizer 需要罗马化，脚本按官方文档走 `uroman` 预处理（`tokenizer.is_uroman` 判定）。
- **运行时降级链**（`src/core/elderVoice.js`）：
  1. 音频包命中 → 播音频（离线可播）；
  2. 音频缺失 → 设备 TTS 优先挑 `nan-TW` / `zh-TW` 声音；
  3. 都不行 → 显式提示「这台设备没有闽南语声音」，并保持普通话可用。
- **失败预案（决策规则，执行时按此判定）**：若沙箱内无法拉取权重（下载失败/耗时异常），则**不阻塞其余 10 项**：保留脚本 + 模板 + `NOTICE.md`，`manifest.json` 写空清单，运行时自动走降级链 2/3；并在最终回复中如实说明「音频包未生成，脚本已就绪可用 `python3 scripts/make-minnan-audio.py` 一键复跑」。（人工试听不可懂时同样退回该预案。）

## 3. 数据模型变更

### 3.1 segment 新增字段（`src/core/agents.js` → `baseSeg`）
```
guide: ''      // 「出站后往哪走」到达指引原文（子女填；长辈端置顶显示）
```
`weather` 不进 segment，而是进**卡片**（由子女端查好后随分享下发）。

### 3.2 分享卡新增列（`packCards` / `expandCards`）
```
[0..12] 不变（[11]=timeOfDay, [12]=todos）
[13] = guide      尾部空位仍裁到最小 7 列
[14] = weather    （卡片级字符串，如「24℃ 多云，带件外套」）
```

### 3.3 子女邀请包新增列（`packInviteSegments` / `buildInviteTrip`）
```
[14] = guide
```

### 3.4 分享载荷新增键（`src/core/share-codec.js`）
```
pr: <首选联系人在 contacts 里的下标>   // 缺省 0；越界回落 0；无家人则 undefined
```

### 3.5 设备级存储（`src/core/store.js`）
```
ptb:elder:last        { token, title, startDate, savedAt }   // 「记住这台手机」
ptb:elder:prefs       白名单扩为 { scale, theme, wake, voice, autoRead }
                       wake: boolean（默认 true）
                       voice: 'zh' | 'nan'（默认 'zh'）
                       autoRead: boolean（默认 true，勾完自动读下一段）
```
- `resolveElderPrefs(sharePrefs)`：`scale/theme` 保持「本机 > 分享 > 默认」；`wake/voice/autoRead` **只认本机**（分享不携带，避免把长辈设备的能力硬写成预设）。
- 「清理缓存与残留」（`ProfilePage`）**不删** `ptb:elder:last` 与 `ptb:elder:prefs`（属长辈自己的选择与便利，不是残留）；只清 `ptb:sync:*`、`ptb:elder:state:*` 与 Cache Storage（维持现状）。

### 3.6 同步事件新增（复用现有 `makeEvent/push`，不改 `sync.js`）
```
sos            segId=''        data={ lat, lng, hasLoc }        // 长辈触发紧急求助
sos-cancel     segId=''                                          // 长按中途松手（仅本机展示，不入链接）
arrive-missed  segId=<段id>    data={ minutes, eta }             // 平安到达超时（本机判定后上报）
guide-viewed   —（不加）                                           // 避免噪声
```
子女端 `EVENT_TEXT` 增三条人话：「长辈按了紧急求助」「长辈取消了求助」「长辈还没确认到达（预计 … 到达，已过 …）」。

### 3.7 presence 扩展（服务端，`server/app.mjs`）
```
presence = { lat, lng, acc, at, eta?: { segId, at } }   // 最近一个"该到了"的到达点
```
- `cleanPresence` 增加对 `eta` 的白名单校验（`segId` 字符串 ≤64、`at` 有限数字），非法则丢弃该字段（其余照旧）。
- `pull` 变为**惰性比对**（不引入后台定时器）：若 `eta.at + 1h < now` 且房间 events 里**没有**晚于 `eta.at` 的 `card-done(segId)`，则在响应里附带合成项 `alerts: [{ type:'arrive-missed', segId, at, data:{ minutes, eta } }]`（`push` 响应不带 `alerts`，避免重复入库）。
- 阈值常量 `ARRIVE_GRACE_MS = 60 * 60 * 1000`（1 小时，与预览示例「已经 1 小时 28 分没有确认」一致）。

### 4.2 建议 2 · 记住这台手机
- `store.js`：`KEYS.elderLast` + `loadLastElderTrip()` / `saveLastElderTrip({token,title,startDate})` / `clearLastElderTrip()`（白名单校验：token 必须形如 `xxx.yyy`，title/startDate 为字符串）。
- `ElderPage.vue`：
  - `submitCode()` 解码成功后 `saveLastElderTrip(...)`（title 取 `payload.title`，startDate 取首张卡日期）。
  - 新状态分支 `state === 'resume'`：无 token 进入 `/e` 且本机有 `last` 时显示：
    - 大按钮（`.big-btn`）「继续上次的行程」+ 第二行小字「《行程名》 · 10 月 11 日出发」；
    - 次按钮（白底描边）「换一个行程」→ 进 `code` 页（并保留用户选择：`clearLastElderTrip()` 由「换一个」触发，避免每次都被拉回）；

### 4.3 建议 3 · 屏幕常亮（Wake Lock）
- `ElderPage.vue`：
  - `requestWake()`：`prefs.wake && navigator.wakeLock && state==='ok' && page==='day'` 时 `navigator.wakeLock.request('screen')`，结果存 `wakeSentinel`；
  - `releaseWake()`：切页/离开/`visibilitychange → hidden`/组件卸载时 `sentinel.release()`；
  - 页面可见时重新申请（Wake Lock 在隐藏后会被浏览器释放）；
  - **不支持时静默**：不弹任何提示，仅把设置页那一行隐藏（`supportsWakeLock()` 判定）。
- `ShowView.vue`：新增「屏幕常亮」开关行（`wake`），说明「看行程的时候屏幕不会自己熄灭」；`supportsWakeLock()` 为 false 时整行不渲染。
- `store.js`：`wake` 进白名单；`saveElderPrefs` 落盘。

### 4.4 建议 4 · 「接下来」引导 + 绝对倒计时
- `upcoming.js` 新增纯函数：
  - `nextDepartText(cards, now)` → 「离 09:35 出发还有 2 小时 15 分」（取 `nextUpcoming` 的 `card.depart` 绝对时刻；无时刻退回 `countdownText`；无下一段返回 `''`）。
  - `arrivalCheckpoints(cards, now, {graceMin})` → 已过到达时刻 + `graceMin`、且未勾「走完」的段（供 #7 复用）。
  - `firstPendingIndex(cards, doneMap)` → 第一个未走完的段下标（供 #4 勾完跳转）。
- `ElderPage.vue`：`nextText` 改用 `nextDepartText`；勾「走完」后：
  1. 计算下一段下标 → 设 `highlightSegId`（复用已有滚动 `scrollIntoView({behavior:'auto'})`）→ 加 `next-pill`「接下来您要去这里」（由 DayView 依据 `nextSegId` 渲染）；
  2. `prefs.autoRead && speaking 支持` 时播一句「接下来您要去……」（复用 `onSpeakClick` 的分句逻辑，新增 `speakOne(text)`）。
- `DayView.vue`：新增 props `nextSegId`；命中卡片渲染 `.next-pill` 与 `card-focus` 描边。

### 4.5 建议 5 · 走完撤销（5 秒提示条）
- `ElderPage.vue`：`onToggleDone` 后再维护 `undo = { key, index, title, at }`；底部渲染 `.el-toast`「刚才把「1 动车」标成了走完 / 手滑点错了？点 撤销（还有 5 秒）」：
  - 点「撤销」→ 调 `toggleDone` 反向 + `push('card-undone')` + 清 `undo`；
  - 5 秒（`setTimeout`）后自动消失；
  - 再次勾选另一段时覆盖旧的 `undo`（只保留最近一条，避免堆叠）。
- 零动画：纯 `v-if` + 文案；倒计时数字由 1s 定时器刷新。
- 与预览一致：**不打断、不弹确认框**。被撤销的段若带 todo 展开状态，保持原样。

- `ElderPage.vue` 顶栏（`page === 'day'`，`state === 'ok'` 时）常驻 SOS 块：

### 4.7 建议 7 · 平安到达确认
- **长辈端本机判定（纯静态降级，必备）**：`ElderPage` 已有 30s 定时器，新增 `refreshArriveWatch()`：
  - 用 `arrivalCheckpoints(cards, now, { graceMin: 60 })` 取超时未确认的段；
  - 命中 → 本机横幅「预计 09:12 到达，现在还没确认『走完』——给阿明打个电话报平安吧」+「好，我知道了」（按 `segId` 去重存 `elderState.dismissed`，键 `segId:arrive`）；

- 阈值：`ARRIVE_GRACE_MIN = 60`（前端与后端共用同一常量语义）。

## 7. 假设与决策

| 项 | 决策 |
|---|---|
| 闽南语音频 | 用 Meta MMS-TTS `nan` 生成静态包（CC-BY-NC-4.0，**非商用**，在 `NOTICE.md` 明确标注）；体积 < 300KB；提供 `VoxCPM2`（Apache-2.0）作为有 GPU 时的商用替换路径；沙箱内生成失败则走降级链并如实说明 |
| 语音优先级 | 分享**不**下发语言偏好：语言是长辈本机选择（避免替长辈决定） |
| 首选联系人 | 分享页显式单选（默认第一位），随 `payload.pr` 下发；长辈端缺省用第一位 |
| 紧急求助 | 浏览器不能自动发短信/打电话 → 走 `tel:` + `sms:` 深链（正文含 OSM 位置链接）；同时 push `sos` 事件让子女端实时看到；长按 1 秒防误触，进度条用 JS 刷新（零 CSS 动画） |
| 平安到达阈值 | 超时 1 小时；前端本机判定为**必备**（纯静态可用），服务端 `pull` 惰性比对为**可选增强**（不引入后台定时器） |
| 天气 | 服务端可选代理 Open-Meteo（免 key，只需城市名，不上报坐标）；无服务端/无网 → 静默无天气，不阻断分享 |
| 长图 | 复用 `export.js` 的 canvas 绘制；长辈端只加一个次按钮，不改子女端现有导出行为与文件名 |
| 缓存清理 | 「清理缓存与残留」不删 `ptb:elder:last` 与 `ptb:elder:prefs`（长辈自己的选择，非残留） |
| 不改范围 | 不顺手改与本 11 项无关的既有 bug；不新增后端账号体系；R1–R9 与在线地图（上一轮已交付）保持不动，除 `agents.js` 加列与 `sync.js` 加 `alerts` 这两处必要兼容改动 |
