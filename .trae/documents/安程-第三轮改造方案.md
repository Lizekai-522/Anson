## 二、现状分析（已核实，非推测）

### 2.1 长辈端导航：单页 + 折叠面板
`src/elder/ElderPage.vue`（839 行，单文件组件）目前是**一个页面**承载全部内容：行程卡列表 + `v-show` 折叠的「家人电话」面板 + `v-show` 折叠的「显示」面板，底栏三按钮 `播报 / 家人 / 显示` 用 `showContacts`、`showDisplay` 两个布尔量切换。

问题：三个板块同页堆叠，展开后面板插在行程卡下方，长辈要滚动、要区分"哪块是刚点出来的"。用户的判断是对的。

### 2.2 二维码不显示：已定量确诊（根因是链接太长）
实测数据（读源码 + 纯函数探针，`encodeShare` → `buildShareUrl` → `encodeQR`）：

| 行程规模 | token 长度 | 链接长度 | M 级 | L 级 | 220px 下每模块宽度 |
|---|---|---|---|---|---|
| 1 段 | 900 | 926 字符 | v25（117 模块） | v21 | **1.88px**（扫不动） |
| 2 段 | 1604 | 1630 字符 | **失败** | **失败** | — |
| 4 段 | 2772 | 2798 字符 | **失败** | **失败** | — |

- 自研 QR 引擎上限 v25（`src/core/qr.js`），2 段及以上的链接**必然超限**，`qrDataUrl` 抛错 → `SharePage.generate()` 的 catch 把 `dataUrl` 置 null → 页面只剩一行小字「行程较长，二维码放不下」。用户看到的"二维码不显示"就是这个。
- 1 段虽然能生成，但 117 模块塞进 220px = 每模块 1.88px，实际扫不出来。
- **测试为什么没发现**：`tests/e2e/walk-kid.test.mjs:67-69` 写的是 `if (qr.count() > 0) … else await waitText(page, '二维码放不下', 4000)` —— 降级分支被当成通过条件。

根因：payload 里塞了可由结构化字段**重新生成**的冗余内容（每段 ~40 字的 `voice` 播报词、`tips` 数组、`icon`、类型词 `title`），单卡就占 400+ 字符。

### 2.3 可复用资产
- `src/core/share-codec.js`：`encodeShare/decodeShare`（`payload.v !== 1` 校验），fnv1a 校验和 + base64url，**已有版本字段，可平滑加 v2**
- `src/styles/global.css`：token 唯一样式入口（`--c-*` / `--f-*` / `--sh-*` / `--r-*` / `--el-*`）
- `src/core/spring.js`：自研弹簧引擎（抽屉拖拽在用，质量已够，保留）
- `scripts/make-icons.mjs`：图标生成脚本（换 logo 时改这里）
- 测试基建：`tests/run-all.mjs`（unit + e2e）、`tests/pwa-prod.mjs`、`tests/screenshots/*.png` 视觉基线

## 三、长辈端改造

### 3.1 导航模型：一个按钮 = 一个页面（真实路由）

**路由设计**（token 只含 base64url 安全字符，不含 `/`，可直接做路径段）：

| 路由 | 页面 | 底栏高亮 |
|---|---|---|
| `#/e/<token>` | 今日行程（默认） | 行程 |
| `#/e/<token>/calls` | 家人电话 | 家人 |
| `#/e/<token>/show` | 显示设置 | 显示 |
| `#/e`（无 token） | 6 位码输码页 | 无底栏 |
| （解码失败/过期） | 恢复页 | 无底栏 |

**底栏**：`行程 / 家人 / 显示` 三个按钮 → 纯导航（`navigate()` 跳路由），当前页按钮用 `aria-current="page"` + 描边高亮。
**播报按钮从底栏移到行程页内**：它是"作用于行程页的动作"，不是页面；放在行程页页头下方的整宽大按钮「听一遍」，比固定底栏更贴近语义，也比底栏更显眼。

**子页面不依赖浏览器返回键**：家人页、显示页顶部各有一个整宽「返回今日行程」按钮（长辈端的返回必须显式、可点、大字）。

**文件拆分**（当前 839 行单文件已过大）：

```
src/elder/
  ElderPage.vue     壳：路由解析 + 状态机('code'/'ok'/'expired'/'malformed') + 底栏 + 主题/字号应用
  DayView.vue       今日行程页：页头 + 听一遍 + 行程卡列表 + 空态
  CallsView.vue     家人电话页：联系人列表 + 拨打 + 微信复制
  ShowView.vue      显示设置页：字大小 3 档 + 主题 3 档
  elder-shared.js   子页面共用的纯函数（contactTitle/contactSub/timeRange/cardKey/copyText…）
```

`App.vue` 的 `isElder` 判断（`route.path === '/e' || startsWith('/e/')`）已能覆盖新路由，**外壳无需改动**。

### 3.2 去掉产品 logo / 印章
- 删除 `.head-seal`（三个页面模板里的「行」印章）与其样式
- 页头改为：`大字日期`（如 `5月20日 星期三`）+ `页面标题`（今日行程 / 家人电话 / 显示）
- **长辈端整页不出现产品名**（「安程」也不出现）——新增断言：长辈端 DOM 文本不含产品名
- 空态/恢复页原有的印章（`安`、`丢` 等）一并去掉，改用大字陈述句

### 3.3 长辈端视觉（学 romemichal.pl）
从参考站提炼可迁移的三条，落到长辈端：

| 参考站特征 | 长辈端落地 |
|---|---|
| 超大字号陈述句做页头（"Pretty is the easy part. I design tools that work."） | 页头用大字陈述句，如「今天 2 段行程」「家人都在这」 |
| 编号分节（01 About / 02 Works / 03 Experience） | 行程卡编号 `01 / 02`，替代图标装饰 |
| 极简、无装饰、靠留白与对齐 | 去掉左侧 8px 强调条 → 改为**粗分隔线 + 大号车次**；去掉圆形图标，改编号；删除卡片阴影 |

**保持不变（适老红线，机器断言守着）**：正文 ≥28px、字重 ≥600、主按钮 ≥72px、触控区 ≥60×60、零动画、三主题对比度 ≥7:1。

## 四、短信 / 邮件：双通道（真实可用）

### 4.1 通道一：系统短信 / 邮件（零配置，永远可用）
新建 `src/core/notify.js`（纯函数，可单测）：

```js
buildSmsHref({ phone, text })    // → sms:13800001111?&body=<encodeURIComponent(text)>
buildMailtoHref({ to, subject, text })  // → mailto:...?subject=...&body=...
notifyPayload({ link, code6, name, tripTitle })  // → 统一的短信/邮件正文
```
正文示例（长辈视角，短、清楚）：
```
【安程】小明的行程已备好，点开就能看：
<链接>
打不开就打开"安程"，输 6 位码：839201
```

### 4.2 通道二：服务端真实发送（配了就用，没配自动回落）
新建零依赖 Node 服务（`node:http`，不引任何 npm 包）：

```
server/
  notify-server.mjs       HTTP 服务：GET /api/notify/config、POST /api/notify
  providers/aliyun.mjs    阿里云短信（HMAC-SHA1 签名，RPC 风格）
  providers/twilio.mjs    Twilio 短信（HTTP Basic）
  providers/resend.mjs    Resend 邮件（Bearer）
  providers/webhook.mjs   通用 HTTP 网关（POST JSON，自建/其它服务商都能接）
  mock-provider.mjs       本地假 provider（联调与 e2e 用，把 *_BASE_URL 指过来即可）
  .env.example            环境变量模板
```

约定：
- `GET /api/notify/config` → `{ sms: 'aliyun'|'twilio'|null, email: 'resend'|'webhook'|null }`（前端据此决定用哪条通道）
- `POST /api/notify` ← `{ channel:'sms'|'email', to, text, subject? }` → `{ ok:true, via:'aliyun' }` 或 `{ ok:false, reason }`
- **安全**：密钥只在服务端读环境变量，前端零密钥；校验同源 `Origin`；配了 `NOTIFY_TOKEN` 时要求 `Authorization: Bearer`
- **回落规则（前端 `notify.js`）**：未配置 / 请求失败 / 超时 3s → 自动改用 `sms:`、`mailto:`，并在 UI 明确告知「已改用你手机上的短信」

### 4.3 子女端 UI（`src/pages/SharePage.vue`）
新增区块「发给长辈」：手机号 / 邮箱输入 → `[发短信]` `[发邮件]` 两个按钮；按钮下方一行小字说明当前走的是哪条通道（"已接通服务端发送" / "将打开你手机上的短信"）。发送后给出明确反馈（成功 / 回落到本机 / 失败原因）。

### 4.4 测试
- `tests/unit/notify.test.mjs`：深度链接构造（中文、换行、特殊字符编码）、正文组装、通道判定、回落判定、阿里云签名固定向量
- `tests/e2e/notify.test.mjs`：起真实 `notify-server.mjs`（`*_BASE_URL` 指向 `mock-provider.mjs`）→ 点发送 → 断言 mock 收到正确请求；**不配 provider** 时断言按钮变成 `sms:` 深链且提示"已改用本机短信"

## 五、二维码修复（三层，缺一不可）

### 5.1 payload 瘦身（主因，`src/core/share-codec.js` 加 v2）
去掉可重新生成的字段，改为解码端水合（hydration）：

| 字段 | 处理 |
|---|---|
| `voice`（每段 ~40 字播报词） | **删除**，解码后由 `src/core/agents.js` 的同一套生成器重生 |
| `tips` | **删除**，同上重生 |
| `icon`、类型词 `title` | 删除，由 `kind` 推导 |
| `gen` | 删除，可由 `exp - ttl` 推回 |
| `cid` | 删除（无消费方） |
| 键名 | 单字母化 + 卡片数组化（`[kind, date, code, from, to, depart, arrive, segId]`） |

- 目标（**写成断言**）：1 段 ≤ 320 字符、2 段 ≤ 550 字符、4 段 ≤ 1000 字符
- **向后兼容**：`decodeShare` 同时吃 v1 / v2 —— 老的分享链接必须仍能打开（新增 e2e 断言：用固定 v1 token 打开长辈端成功）
- 水合函数 `hydratePayload(p)` 放 `src/core/agents.js`，与 `buildElderCards` 共用同一套文案生成逻辑，保证「解码后 = 编码前」

### 5.2 QR 渲染策略（`src/core/qr.js` + `SharePage.vue`）
- `moduleSize` 按最终模块数反推，保证**每模块 ≥ 2.4px**；承载尺寸从 220 提到 **248**
- 分级：先 M，M 失败退 L（保留现有逻辑）；两者都失败才算"装不下"
- 静区 margin 保持 4 模块（扫码必需）

### 5.3 降级 UI 改对 + 测试收紧
- 装不下时不再只显示一行小字，改为**三条可执行路径**：① 复制链接 ② 6 位码 ③ **发短信/发邮件**（与 §4 打通）
- 测试：`walk-kid` 的降级分支删掉，改为**短行程必须生成二维码**（`img[alt*="二维码"]` 存在 + `naturalWidth > 0` + 每模块 ≥ 2.4px）

## 七、子女端：编辑式排版 + 去 AI 味 + 动效升级

### 7.1 参考站提炼与落地（recent.design）
| 参考站特征 | 子女端落地 |
|---|---|
| 克制的网格与标签体系（All / Web / Interface / Motion 芯片） | 列表页用**筛选芯片 + 网格**替代卡片墙；行程段用网格对齐展示 |
| 细线分隔、极少阴影 | token 层去掉卡片阴影（仅浮层保留），改用 1px 细线 |
| 单一强调色、留白主导 | 朱红收窄到"主操作 / 当前态 / 关键数字"，其余走墨色阶 |
| 动效克制、有节奏、只在需要处 | GSAP 过渡统一 180–240ms，只用 transform/opacity |

### 7.2 token 与排版（`src/styles/global.css`）
```
底色     #FDFBF5(暖黄) → #FBFBF9(中性纸白)
卡片     白 + 阴影      → 白 + 1px 细线，无阴影
圆角     8/12/16       → 4/6/8（编辑器气质）
新增     --f-mono（车次/时间/6 位码用表格数字）、--fs-display（陈述句大字）
删除     .glow-layer 发光层
```
页面头部统一为编辑式：`编号 + 大标题 + 一句话`（如 `01 / 行程  ·  G9901 · 2 段`）；区块用分隔线切分而非卡片包裹；文案瘦身，去掉形容词式表达。

### 7.3 动效（GSAP）
- 新增依赖 `gsap`（core，~27KB gzip；按需引插件）
- 三处编排（用户要求"可用做好一点"）：
  1. **页面切换**：内容区 `y:8→0 / opacity:0→1`，180ms
  2. **列表入场**：卡片 stagger 40ms（仅首次进入某页，用 `sessionStorage` 标记避免来回切页重复播放）
  3. **6 位码**：逐位翻入（分享页的仪式感）
- **`prefers-reduced-motion` 统一关断**（读同一处判断），并加断言：reduced 模式下 `getAnimations()` 为空
- 现有 `spring.js` 继续服务抽屉拖拽（物理手感），与 GSAP 分工不重叠
- 性能：只动 `transform/opacity`，`will-change` 用完即撤

### 7.4 长辈端零动画不受影响
长辈端仍不引 GSAP、不写 animation/transition，`a11y` 测试的 `animatedCount === 0` 断言继续守着。

**功能验收**
- 长辈端：底栏三按钮各跳一个**独立整页**；子页有「返回今日行程」；长辈端 DOM 不含产品名与印章
- 二维码：1 段 / 2 段 / 4 段行程都能出码且每模块 ≥2.4px；4 段以上超限时给出复制链接 / 6 位码 / 发短信邮件三条路径
- 短信邮件：配了 provider（指向 mock）时点发送 → mock 收到请求；未配时点发送 → 落到 `sms:` / `mailto:` 且 UI 明确告知
- 改名：页面标题、manifest、单文件产物名、备份文件名、README 全部为「安程」；无残留「爸妈出行宝」（`grep` 断言）

**质量验收**
- `npm test` 全绿：单元（含新增 notify / codec-v2）+ 端到端（含新增 elder-nav / notify）
- `npm run test:pwa` 全绿（离线仍可渲染）
- `npm run build:single` 通过（`dist/安程-单文件.html`，file:// 冒烟）
- 长辈端硬指标全绿：正文 ≥28px / 字重 ≥600 / 按钮 ≥72px / 触控 ≥60×60 / **零动画** / 三主题对比度 ≥7:1
- reduced-motion 下 `getAnimations()` 为空
- 视觉基线全部重出并目检（长辈端三页 + 子女端各页 + 移动端）
- 新端口预览（绕开 service worker 缓存；sw 已是导航网络优先）
- 包体：gzip 增量 ≤ +35KB

**计划外不做**
- 不部署真实短信/邮件网关；不接支付/地图/天气；不改适老红线；不动 v1 链接格式
