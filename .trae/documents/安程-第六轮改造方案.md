# 安程 · 第六轮改造方案

> 本轮目标（9 项）：
> R1 长辈端回主页 · R2 行程可解析/记录「游玩安排」 · R3 卡片内 todo 清单 · R4 长辈勾选 todo 实时同步回子女端 ·
> R5 家人可单独配置「他对我的称呼」 · R6 旧缓存清理 · R7 分享页展示/选择本次包含的家人 · R8 家人分组（一人可属多组）· R9 行程可分享给其他子女账号。
>
> 硬约束：
> 1. 长辈端适老化红线不破 —— 正文 ≥28px、主按钮 ≥72px 高、触控区 ≥60×60、三主题正文对比度 ≥7:1、全页零 CSS 动画（不写 animation/transition）。
> 2. 解析必须**通用** —— 用户给的示例只是**形态参考**；**任何示例里的具体城市/景点/街区/酒店名一律不得写进代码、测试、文档常量**。词表只放结构性词汇与仓库既有的 `CITIES` 列表。
> 3. 账号只存本机（无后端账号体系）—— 一切「分享给其他账号」都走**自包含链接/6 位码**，不引入后端账号。

## 3. 设计方案

### 3.1 数据模型

```
segment 新增字段（所有段类型都有）：
  timeOfDay: '清晨'|'早上'|'上午'|'中午'|'下午'|'傍晚'|'晚上'|'夜里'|'凌晨'|''   // 可空
  todos:     [{ id, text, level }]     // level ∈ 'high'|'normal'|'low'
新增段类型：
  type:'activity'   // 游玩/安排：不是"出发到达"，而是"到这里做什么"
    to: 地点名（通用抽取，取不到留空）
    note: 攻略原文那句说明（原样保留，供长辈端"展开看"）

账号桶新增（store.data）：
  familyGroups: [{ id, name, memberIds:[familyId, …] }]   // 一个家人可属多个组
  invites:      [{ id, tripId, token, code6, createdAt, exp, title, contactNames }]  // 子女邀请记录

localStorage 新增（设备级）：
  ptb:pending-invite   未登录时点开子女邀请链接，暂存 token，登录后自动继续接收
```

- `todos` / `familyGroups` / `callsMe` 随 `trip`、账号桶持久化（走既有 `persist()`）。
- 长辈端 todo 勾选状态**不进 trip**，按 room 存本机（`elderState.todos`），键 `${cardKey}:todo:${index}`，值 = 时间戳。与 `done/collapsed/dismissed` 同一套隔离与白名单校验。
- 优先级编码：`'normal'→0`、`'high'→1`、`'low'→2`（编解码单一映射常量）。

### 3.2 解析（R2：通用、可解释、默认要人确认）

在 `parseSegments` 逐行循环内新增 `activity` 识别，**只用通用词表**：

1. **天标记扩展**：现有 `^(第N天|次日|隔天|当天|同天)` 追加英文 `Day\s*N`（大小写不敏感），统一相对天偏移。
2. **时段词**：命 `清晨|早上|上午|中午|下午|傍晚|晚上|夜里|凌晨` → 记 `timeOfDay`（取首个）。
3. **交通优先**：先跑现有 `isFlight/isTaxi/isHotel/isTrain`；命中即走原分支（不改既有行为）。
4. **activity 判定**：未命中交通/住宿，且满足任一：① 有时段词；② 形如 `X：Y` 小标题（分隔符 `：`/`:`/`·`，冒号后非空且不含交通关键词）；③ 含动作结构词 `去|前往|逛|游|玩|参观|打卡|散步|休息|吃饭|午餐|晚餐|入住后|到…后`。
5. **地点抽取**：复用 `extractFromTo/normalizeStation/guessCity`；对 `去X`、`在X`、`从X到Y`、`X（站|机场|街|公园|广场|古镇|寺|塔|博物馆|商场|美食街）` 等通用模式取 `to`；取不到 → `to=''` 且 `manualConfirm=true`。
6. **标题**：`timeOfDay + ' ' + (to || 冒号后小标题)`。
7. **长句归并**：无时段词、无交通/住宿特征、长度 ≥12 字的散文行 → 并入**上一条 activity 的 `note`**（`note ? note+'；'+line : line`）；上一条不是 activity 则新开 activity（`to` 可能空、`manualConfirm=true`）。**不丢原文**。
8. **兜底**：仍不满足者进 `unparsed`（保持现状）。
9. **合理性**：`sanityCheck` 对 activity 新增 `activity-place-missing`（缺地点，`info`），`ISSUE_LABEL['activity-place-missing']='缺地点'`。activity 同时拿到「日期 + 地点/标题」才不加 `manualConfirm`。

> **不过拟合红线**：新增词表只含**结构性词汇**（时段、方位、`去/逛/玩/游/参观` 等动作词、`day/第N天`）与既有 `CITIES`；**不得**出现示例中的任何景点/街区/酒店名。测试用自造通用地名，不复制示例文本。

### 3.3 编码（R2/R3/R5 随长辈链接下发，向下兼容）

- `packCards`/`expandCards`：`CARD_TYPES` 追加 `'activity'`（索引 4）；行新增列 `[11]=todos`，紧凑 `[[text,lv],…]`，`lv∈0/1/2`，尾部空数组不写；裁剪边界仍「最小 8 列」；`expandCards` 读 `c[11]` 缺失 → `[]`。
- 新增**导出纯函数** `packTodos/expandTodos` + `TODO_LEVELS`，编解码共用单一实现。
- `packPeople/expandPeople`：追加第 6 列 `callsMe`；裁剪边界仍「最小 2 列」；旧链接解出 `callsMe=''`。
- **不新增版本号**；`unpackPayload` 缺字段回落空值，保持 v2 兼容。

### 3.4 同步（R4）

## 5. 假设与决策

| 项 | 决策 |
|---|---|
| 示例不过拟合 | 词表只含结构性词汇 + 既有 `CITIES`；示例里的具体景点/街区/酒店名**一律不进代码/测试/文档**；测试用自造通用地名 |
| activity 解析质量 | 规则优先；不确定一律 `manualConfirm=true` + 进 `issues`；散文归并进 `note`；复杂攻略仍可用既有「AI 一键补全」 |
| todo 优先级 | 三档「重要/普通/随手」，**色块+文字标签双通道**；色块仅装饰，文字走 `--el-ink`，三主题均 ≥7:1 |
| todo 勾选状态 | 存长辈端本机（按 room），子女端靠同步事件实时反映；**不回写 trip** |
| 退出/回主页 | 长辈端无登录，实为导航回主页：有账号去 `/home`，否则 `/`；保留原「返回行程」 |
| 「他对我的称呼」 | 新增 `family[].callsMe`，仅长辈端家人电话页展示 |
| 家人分组 | `familyGroups`，成员可属多组；家人页管理；分享时按组**快捷勾选**（不改变"一次分享一份 contacts"的本质） |
| 本次家人 | **每次生成分享时**选择/确认（默认全选），结果与分享记录展示姓名；不把家人清单持久写进 trip |
| 子女间分享 | **自包含链接 + 6 位码导入**（同设备码可扫本机桶）；收到后复制为**新 trip** 进接收者账号桶；`importedFrom` 防重复；**不新增后端账号** |
| 6 位码范围 | 与长辈端一致：**同设备**有效；跨设备用链接 |
| 缓存清理 | ① SW 升级自动卸旧；② 启动自愈**只**清孤立 `ptb:sync:*`（不碰 elder state）；③ 个人页手动清 Cache Storage + 两类残留键 + reload |
| 不改范围 | 不顺手修 Debug 清单里与本需求无关的 bug；如需一并修请另行确认 |
| 红线 | 长辈端字重/尺寸/触控/对比度/零动画沿用现有守卫（`elder-overflow`/`elder-a11y-plus` 守着） |
