### 1.1 「改成按钮」的 HTML 约束（关键前提）
两个 `span.entry-cta` 的**父元素已经是 `<button class="entry">`**（整行可点，触控区大）。HTML 不允许 button 嵌套 button，**不能**把它替换成真正的 `<button>` 子元素，否则整行点击与选中态都会坏掉。
→ 结论：`.entry-cta` 保持 `span`，改为**按钮外观**（描边 + 内边距 + hover 填充），行本身仍是按钮。这就是「整齐效果」下的正确解。

## 二、调研结论：同类产品的自定义模型配置（对标）

对标对象与共同字段（综合 Cherry Studio / Chatbox / LobeChat / NextChat 的"添加模型/供应商"表单，以及 OpenAI 兼容协议）：

| 字段 | 是否必备 | 说明 | 本项目取值 |
|---|---|---|---|
| 供应商预设 | 强烈建议 | 选预设自动填 baseUrl/默认模型名 | 内置 OpenAI / DeepSeek / 通义千问 / Ollama / 自定义 |
| Base URL | **必备** | OpenAI 兼容根，形如 `https://api.x.com/v1` | 存原文，请求时拼 `/chat/completions`（去掉尾部 `/`） |
| API Key | **必备** | `Authorization: Bearer <key>` | 仅存本机 localStorage，明文，页面明示风险 |
| 模型名称 | **必备** | 如 `gpt-4o-mini` / `deepseek-chat` | 与 baseUrl 同级保存 |
| 是否支持视觉 | 建议 | 决定能否用截图识字 | 布尔开关，默认跟随预设 |
| 温度 | 可选 | 结构化解析宜低温 | 默认 0.2，可调 |
| 自定义请求头 | 可选 | 少数中转网关要额外头 | 本轮**不做**（避免过度设计） |
| 走服务端代理 | 建议 | 解决 CORS / 密钥不进浏览器直连 | 布尔开关，默认关 |

**协议共识（三家一致）**：`POST {baseUrl}/chat/completions`，body `{ model, messages, temperature }`，回包取 `choices[0].message.content`；多模态把 `content` 换成 `[{type:'text'}, {type:'image_url',image_url:{url}}]`。
**CORS 现实**：多数官方端点不允许浏览器跨域；Ollama 需 `OLLAMA_ORIGINS=*`。→ 这正是「直连优先、失败回落代理」的由来。

### §C agent 优化（规则层补召回 + AI 补漏层）
**边界铁律不变**：`sanityCheck` 永远最后跑；AI 输出视为"建议"，只允许填补空缺，不允许覆盖规则已确认的非空值。

**C1 规则层（[agents.js](file:///workspace/src/core/agents.js)，纯 JS，可单测）**
- 去掉 `parseDatePhrase` 里 `10.8` 的**正则后行断言** `(?<![\d.])`（Safari <16.4 不支持，会整条日期解析失效）→ 改用捕获组 + 边界判断。
- `extractFromTo` 增加「返程 / 回程 / 去程」前缀处理，及 `A→B` 中带空格站名（如「上海 虹桥」）的清洗。
- 站名别名表补一批常见站（深圳/广州/杭州周边等），并在归一时统一补 `站`。
- 酒店：下一段若为次日高铁且无显式晚数，保留 `hotelNights=1` 但在 `sanityCheck` 输出 `info` 提示"住宿天数未写明"，不再静默。
- 每条改动配单测（见 §F）。

**C2 AI 补漏层（新文件 [ai.js](file:///workspace/src/core/ai.js)）**
- `buildAssistMessages(result, { today, fallbackDate })`：把 `unparsed` 行 + `manualConfirm` 段（缺 date/departTime/arriveTime/code/from/to）序列化成请求，要求模型**只回 JSON**（schema 固定），不含解释。
- `applyAssist(result, patches)`：按 `segId` 匹配；只写**空字段**；新增段必须走 `baseSeg` 契约；写入后标 `aiAssisted:true` + `manualConfirm` 保持可核对；最后 `refreshPlain` + 重跑 `sanityCheck`。
- `parseJsonLoose(text)`：剥离 ```json 围栏、截取首个 `{...}`，解析失败返回 null（不抛）。
- 未配置模型 / 请求失败 → `{ ok:false, reason }`，页面只给提示，不报错不阻塞。
- 视觉：`extractTextFromImage(dataUrl)` 走多模态消息，仅当 `config.vision` 为真时按钮可用。

## 四、假设与决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | `.entry-cta` 保持 `span`，只改外观 | 父级已是 `<button>`，嵌套 button 非法会破坏整行点击 |
| 2 | zip 打包放在改动之前 | 用户要的是"当前版本"的快照，必须先冻结再迭代 |
| 3 | 模型配置走**设备级** `ptb:model`，不进账号桶 | 与 `ptb:elder:prefs` 同思路；密钥不该跟着账号同步 |
| 4 | 自定义请求头本轮不做 | 避免过度设计；预设 + baseUrl 已覆盖绝大多数场景 |
| 5 | AI 只填空、不覆盖，`sanityCheck` 永远最后 | 产品的道德底线：宁可标"待确认"，不给确定的错误答案 |
| 6 | `.ics` 用浮点本地时间，不写 TZID | 规避时区库依赖；家庭行程全在同城/邻城，浮点时间足够 |
| 7 | 长图用 canvas 2D 手绘，不引 html2canvas | 零依赖，且能精确复刻长辈端卡片视觉 |
| 8 | 截图识字结果只填进输入框，不自动解析 | 让用户先看一眼识别结果，符合"先核对再导入"的既有交互 |
| 9 | `VALARM` 提醒按成本决定 | 若 RFC5545 实现扎实就纳入；否则记录为后续项，不硬塞 |
