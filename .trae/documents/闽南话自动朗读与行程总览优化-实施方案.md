# 闽南话自动朗读修复 + 行程总览（天气 / 日历 / 地图）页内可见 — 实施方案

## 一、Summary（要做什么）

用户反馈两件事：

1. **闽南话「第二遍是普通话」**：长辈选了闽南话，但「走完了」之后自动朗读的那一句仍用普通话。经确认，指的就是 `guideToNext → speakOne` 这条恒用 `zh-CN` 的路径。
2. **「查目的地天气」「导出日历」以及接入的地图都不能在页面里直接看见**：目前天气只以 toast + 每段一行小字呈现，日历只有下载、没有页内预览，地图组件只用于「某人的实时坐标」、行程目的地根本没有地图。
   → 目标：在行程页里新增一个「行程总览」区，把**目的地天气、按天日历、目的地路线地图**直接铺在页面上。

本次改动覆盖 4 个特性 + 1 项联调启用项，落点集中在长辈端朗读逻辑、行程页、地图组件/数学、以及服务端一个只读接口。

## 三、Proposed Changes（改哪些文件 / 怎么改 / 为什么）

### 改动 1：闽南话自动朗读遵循语言偏好 — `src/elder/ElderPage.vue`

**Why**：`guideToNext` 的 autoRead 忽略了 `prefs.voice`，导致选闽南话后仍播普通话。

**How**：
1. 从 `speakNan` 里抽出**单张卡播放**核心（保持行为不变）：
   ```js
   // 播放一条已决策的语音项；返回是否「降级/失败」
   async function playResolved(v) {
     if (v.mode === 'pack') {
       const played = await playAudio(v.src)
       if (played) return false
       // 放不出音频 → 退回设备 TTS（沿用现有语言字段）
     }
     const spoke = speakText(v.text, v.mode === 'pack' ? (v.lang || 'nan-TW') : v.lang, v.voice)
     return !spoke
   }
   ```
2. 新增「只念某一张卡」：
   ```js
   async function speakCardNan(card, index) {
     const v = resolveVoice({ voice: 'nan', card, index,
       manifest: nanManifest.value || { items: {} }, deviceVoices: deviceVoices() })
     if (v.mode === 'none') return false          // 设备无闽南语能力
     stopNanAudio(); try { window.speechSynthesis.cancel() } catch {}
     speaking.value = true
     try { return !(await playResolved(v)) }       // true = 正常播完
     finally { speaking.value = false }
   }
   ```
3. `speakNan()` 改为循环内调用 `playResolved`（逻辑等价，`degraded` 与两处 `voiceNotice` 文案保持原样）。
4. 改 `guideToNext`：
   ```js
   if (prefs.value.autoRead) {
     if (prefs.value.voice === 'nan') {
       speakCardNan(card, i).then((ok) => {
         if (!ok) { voiceNotice.value = '这台设备没有闽南语声音 —— 先用普通话说这句'; speakOne(nextSpeech(card, '接下来您要去：')) }
       })
     } else {
       speakOne(nextSpeech(card, '接下来您要去：'))
     }
   }
   ```
   - 闽南话可用 → 播闽南话（`nanPhrase`，与「听一遍」同源）；设备确实没有闽南语能力时才如实回退普通话并显示提示（保持既有「诚实降级」哲学）。

**不改**：`speakText` 的 `u.lang = lang || 'zh-CN'`、`speakNan` 的 pack→TTS 兜底语种、音频包内容。

### 改动 3：RealMap 支持多点（目的地路线） — `src/components/RealMap.vue` + `src/core/map.js`

**Why**：要给一串目的地画图，而组件目前只接受单个坐标。

**How（map.js 新增纯函数，便于单测）**：
```js
// 多点在给定像素宽高内自动取景：返回中心与缩放级别
export function fitPointsViewport({ points, width, height, padding = 28, tileSize = TILE_SIZE, minZoom = 3, maxZoom = 16 }) {
  // 1) 过滤有效点；0 点→null，1 点→{center:该点, zoom:14, markers:[{...中心}]}
  // 2) 在 zoom=0 的墨卡托归一坐标上取 bbox；对每个 zoom 求像素跨度
  //    spanPx(z) = span * 2^z * tileSize；取满足 spanPx<=可用宽/高 的最大 z
  // 3) center = bbox 中心（经度取平均；纬度用墨卡托 y 反算）
  // 返回 { center:{lat,lng}, zoom, markers:[{lat,lng}] }
}
```
`RealMap.vue`：
- 新增 prop `points: { type: Array, default: () => [] }`，元素 `{ lat, lng, label?, order? }`。
- `validPoints = computed(() => points.filter(p=>isValidLatLng(p.lat,p.lng)))`。
- 计算 `view`：
  - 多（`validPoints.length >= 1` 且传了 `points`）→ 用 `fitPointsViewport` 得 center/zoom，再 `viewportTiles` 拿瓦片；用 `map.js` 新加的 `projectPixel({lat,lng,zoom,left,top,tileSize})` 把每个点算成像素位置。
  - 否则 → 走原有单点 `lat/lng` 路径（**完全向后兼容**，长辈端两处不受影响）。
- 模板：`points` 模式渲染编号标记（`.amap-marker` + `.amap-marker-no`），单点模式沿用现有标记；`label` 用于左上角胶囊。

`map.js` 另加 `projectPixel()` 纯函数。

## 四、Assumptions & Decisions（假设与决策）

1. **已与用户确认**：闽南话问题 = 「勾完自动读仍是普通话」，只改 autoRead 路径；地图 = 行程页内嵌目的地地图（无服务端显示提示，用户已接受）；日历 = 页内时间轴/日历预览，导出按钮保留。
2. **地图数据源**：沿用 Open-Meteo geocoding（不引入地图 SDK），只传城市名，隐私取舍与天气一致；瓦片仍用 OSM 栅格。
3. **地图降级**：无服务端 / 城市定位失败 → 面板显示提示文案，不阻塞页面、不弹红 toast。
4. **不新增浮层**：总览用页内 `paper-card`（复用 `.assist-preview` 范式），不接入 App.vue 抽屉，符合「普通内容不用阴影/浮层」的既有规范。
5. **向后兼容**：`RealMap` 单点用法（长辈端两处）保持原样；`buildIcs`/`downloadIcs` 不改语义。
6. **日历预览是「按天摘要」而非完整段列表**，避免与下方 `seg-list` 重复占屏。
7. **不做**：不改音频包内容、不改分享链接格式、不改长辈端卡片的天气胶囊。
